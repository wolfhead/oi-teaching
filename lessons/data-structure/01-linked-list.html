链表：改得快，找得慢

C++ 小课堂 · 数据结构 —— 指针链表、数组模拟，和为什么竞赛只用后者

这一篇的路线

  2. 链表的想法：不连在一起，各自记住"下一个在哪"
  3. 链表的代价：想拿第 5 个，只能从头数
  4. 三个基本操作（遍历 / 插入 / 删除）
  5. OI 的写法：用数组模拟链表 —— 以及为什么快近千倍

先想想数组的麻烦

数组像一排连在一起的储物柜，编号 0、1、2、3……

好处很明显：你要第 5 个，直接走到 5 号柜，一步到位。

但麻烦也很明显——想在中间插一个怎么办？

原来：  [A][B][C][D][E]
想在 B 后面插入 X：
        [A][B][X][C][D][E]
         ↑      ↑
       不动    C、D、E 全都要往后挪一格！

数组是连在一起的，中间塞不进东西，只能把后面所有元素都搬一遍。如果有一百万个元素，插一个就要搬一百万次。

链表的想法：不要连在一起

链表说：既然连在一起这么麻烦，那我们就不连在一起。

每个元素单独放，但是每个元素额外记一件事：下一个在哪儿。

Anext→ Bnext→ Cnext→ NULL

每个方块叫一个节点（Node），里面装两样东西：值，和指向下一个节点的箭头。最后一个节点的箭头指向 NULL，表示"到头了"。

在 C++ 里长这样：

struct Node {
    int val;      // 装的值
    Node* nxt;    // 指向下一个节点（箭头）
};

现在再看插入

要在 A 和 B 中间插入 X：

Anext→ Xnext→ Bnext→ Cnext→ NULL 
Node* x = new Node{99, nullptr};
x->nxt = a->nxt;    // X 指向原来 A 指向的那个（也就是 B）
a->nxt = x;         // A 改成指向 X

只改两个箭头，两步搞定。B、C 一个都不用动，哪怕后面有一百万个节点。

但是，链表也有代价

想拿第 5 个元素？没有捷径。必须从头开始一个一个走：A → B → C → D → E。

数组是"直接走到 5 号柜"，链表是"从第一个开始数五下"。

数组 vs 链表 · 一张表看懂

数组链表
取第 k 个O(1) 一步到位O(n) 得一个个走
已知位置，插入/删除O(n) 后面全要搬O(1) 改两个箭头
要不要提前知道大小要（或者扩容+拷贝）不用，随时加
内存长什么样连成一片散落各处
额外空间没有每个节点多存一个箭头
记住这个取舍：
数组：找得快，改得慢。
链表：改得快，找得慢。
没有哪个更好，只有哪个更适合你要解决的问题。

三个基本操作

① 遍历（从头走到尾）

for (Node* p = head; p != nullptr; p = p->nxt) {
    cout << p->val << " ";
}

p = p->nxt 就是"顺着箭头走一步"。这是链表最核心的一行代码。

② 在节点 p 后面插入

Node* q = new Node{value, nullptr};
q->nxt = p->nxt;   // 新节点接上后面
p->nxt = q;        // p 接上新节点
// 顺序不能反！反了就把后面全弄丢了
为什么顺序不能反？如果先写 p->nxt = q，那 p 原来指向谁就再也找不到了——那条链的后半段就永远丢了。这是写链表最经典的错误，一定要想清楚。

③ 删除节点 p 后面的那个

Node* dead = p->nxt;
p->nxt = dead->nxt;   // 跳过它
delete dead;          // 释放掉

OI 的写法：用数组模拟链表

现在讲一个重要的东西。竞赛里几乎不用上面那种指针链表，而是用数组模拟。

想法很简单：用"下标"代替"指针"。

下标0123
valABCX
nxt32-11

怎么读这张表？从 0 号开始：val[0]=A，nxt[0]=3 → 跳到 3 号：val[3]=X，nxt[3]=1 → 跳到 1 号：val[1]=B，nxt[1]=2 → 跳到 2 号：val[2]=C，nxt[2]=-1 → 结束。

读出来就是 A → X → B → C。和上面那个指针链表一模一样，只是箭头从"内存地址"变成了"数组下标"，-1 代替了 NULL。

const int N = 100005;
int val[N], nxt[N];   // 两个数组就够了
int head = 0, cnt = 0;

// 在 p 后面插入一个值 v
void insert(int p, int v) {
    ++cnt;                // 用第 cnt 号位置当新节点
    val[cnt] = v;
    nxt[cnt] = nxt[p];
    nxt[p] = cnt;
}

为什么竞赛要这么写？三个理由

  1. 不会内存泄漏——根本没 new，也就不用 delete，少一整类 bug
  2. 好调试——出错了直接把 nxt 数组打印出来，一眼看到整条链。指针版你只能看到一堆十六进制地址
  3. 快得多——这条最重要，看下面的数据

CPU 读一个数时会顺手把旁边一片都读进来。数组正好顺了它的意，链表每次都让它猜错。

真实测试：遍历 500 万个数求和

做法耗时倍数
连续的数组0.7 ms1x
指针链表（节点挨着分配）7.2 ms10x
指针链表（节点散落各处）656 ms963x

同样的数据、同样的加法，只因为内存里是"顺着走"还是"到处跳"，差了将近一千倍。

原因是 CPU 有个叫缓存的东西（它是怎么回事，在「内存、栈与缓存」里细讲）。它读一个数的时候，会顺手把旁边一片都读进来——因为它猜你接下来多半要用旁边的。数组正好顺了它的意；指针链表到处乱跳，每次都猜错，每次都要重新去内存里捞。

所以数组模拟链表 = 两头的好处都占：
链表的本事（改箭头就能插入删除）+ 数组的内存布局（连成一片，缓存友好）。

不是因为竞赛选手不会写指针，是因为这么写又快又不容易错。

练习题

五关，按顺序做，每一关都建立在前一关上面。

第 1 关 手写单链表

用 struct Node 和指针，实现一个能做这四件事的单链表：

  • insert(p, v) — 在节点 p 后面插入值 v
  • remove(p) — 删掉 p 后面那个节点
  • print() — 从头到尾打印一遍
  • find(v) — 找到值为 v 的节点，返回指针（找不到返回 nullptr）

测一测：插入 1 2 3 4 5，删掉 3，再在 2 后面插入 99，打印应该是 1 2 99 4 5。

注意：写 insert 的时候想清楚两行的顺序，反了会丢掉半条链。

第 2 关 换成数组模拟

同样的四个功能，改用 val[] 和 nxt[] 两个数组实现，把指针换成下标，NULL 换成 -1。

做完对比一下：哪个版本代码更短？出 bug 的时候哪个更容易查？（试试直接打印整个 nxt 数组）

第 3 关 约瑟夫环 · 链表版

题目：n 个人围成一圈（编号 1 到 n），从第 1 个人开始报数，报到 m 的人出圈，然后从下一个人重新从 1 开始报。问最后剩下的是几号？

例：n=5, m=3 → 出圈顺序是 3、1、5、2，最后剩下 4。

用循环链表做：把最后一个节点的 nxt 指回第一个，就成了一个圈。然后一边走一边删。

第 4 关 约瑟夫环 · 数组模拟版

同一道题，换成 nxt[] 数组实现。感受一下调试起来是不是轻松多了。

第 5 关 约瑟夫环 · 不用链表

这一关是重点。

前面两种做法都要一个一个走过去数，复杂度是 O(n×m)。如果 n 和 m 都是 100 万，会超时。

但这道题其实有个 O(n) 的数学递推公式，一个循环就能算出答案，一个链表都不需要。

提示：设 f(n) 表示 n 个人时最后活下来的编号（从 0 开始编号），试着找出 f(n) 和 f(n-1) 的关系。想想第一个人出圈之后，剩下的问题是不是又变成了一个"n-1 个人的约瑟夫环"，只是起点挪了 m 位。

这一关想通了，你就会明白 OI 里最重要的一句话：
换一个更好的算法，比换一个更好的数据结构有用得多。
