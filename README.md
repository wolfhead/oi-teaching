# OI 教学材料

给孩子准备信息学竞赛（CSP-J 方向）的 C++ 教学材料。

每篇课程是一个**自包含的 HTML 文件，双击就能在浏览器打开**，不需要联网、不需要装任何东西。

---

## 课程

课程按**主题分类**存放，而不是按讲课的先后顺序 —— 这样后面补内容时，新的一篇直接落进对应的分类里。

### 建议的阅读顺序

分类是为了好找，不是阅读顺序。第一次读按这个来：

1. 数字数到头了会怎样？（系统）
2. 什么时候该听老工程师的（经验）—— 它讲的就是第 1 篇里那场争论
3. 链表：改得快，找得慢（数据结构）
4. 内存、栈与缓存（系统）

## 跑实验

课程里所有的性能数字都不是编的，是真跑出来的。想验证或者在新机器上重测：

```bash
bash experiments/run_all.sh
```

会依次编译并运行全部实验，打印环境信息和每项结果。

**注意：数字会波动。** 同一台机器重跑，"链表比数组慢多少倍"可能是 963x，也可能是 858x 或 1255x。
换机器（尤其换 CPU 架构或操作系统）差异更大。看到对不上不用慌，量级对就行。

有几个实验**故意会崩**（栈溢出、递归爆栈），退出码 139 是预期结果，不是脚本坏了。

## 给孩子的用法

1. 打开 HTML，从头读一遍
2. 做篇末的练习题 —— **按顺序做**，每一关都建立在前一关上
3. 做完对照"自测清单"，能不查资料答上来就算过关
4. **课程里所有的实验，都值得自己再跑一遍**

最后一条是重点。这些课反复在讲同一件事：

> 不管是老师说的、爸爸说的，还是这份文档说的，**最后都以你自己跑出来的结果为准**。

## 给协作者 / AI Agent

动手前先读这几条约定：

- **课程按主题分类存放**（`data-structure/` `system/` `experience/` `algorithm/`），一篇只归一类。
  跨类的内容用**互相链接**保住上下文 —— 不要为了分类干净就删掉跨类的那一段
- **课程里出现的每一个性能数字，都必须来自 `experiments/` 里真跑过的代码。** 不许估算，不许凭印象
- 数字会波动，引用时优先用量级表述（"差了近千倍"）；改动实验代码后要重跑，并同步更新引用它的课程
- 技术示意图（内存布局、扩容过程、链表节点）**一律手写内联 SVG**。AI 生图画技术图不能用：
  箭头会反、文字会乱码、改一个数字要重生成整张
- 课程 HTML **自包含**，不引用任何外部资源，双击就能打开
- **不要替孩子写练习题的答案代码。** 练习题只给题面、提示和验收标准

更详细的项目约定和接续状态保存在本地，未纳入版本库。
